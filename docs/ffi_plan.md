## 0. 目标与非目标

**目标**

1. 三言程序能调用 Python 库（numpy/requests/json/…）——解释器路径，进程内零拷贝句柄。
2. 三言程序能调用 C 库——解释器路径走 ctypes；编译路径走 LLVM extern + 链接（唯一
   能同时活在两个执行后端的外语层）。
3. 外调边界统一为**三态信封**：成功→`真`+值、异常→`假`+错误、超时/未知→`可能`——
   与既有 `链()`/`解包()`/`信度守卫()`/`匹配3` 无缝互操作。这是三言相对其它语言 FFI
   的差异化设计，值得当成语言特性讲。
4. 安全默认关闭（`SANYAN_FFI=1` 显式开启），与 `沙箱()` 机制、agent 红线（P5）对齐。

**非目标（本 RFC 明确不做）**

- TypeScript / JS：无三言侧运行时协同（需内嵌 JS 引擎），`.d.ts` 类型导入在动态三态
  语言里无处可接。等出现真实用例再立项。
- Python **AST 转译**（Python 源码 → 三言）：等于造残缺 CPython，库接入价值为零。
- C **全语义导入**（宏展开语义/内联函数体/K&R）：编译器级工程。只导声明。
- 回调（三言函数传给外语侧回调）：阶段 1 一律 fail-closed 拒绝，见 §3.4/§4.3。
- 跨语言 GC/所有权自动化：句柄显式释放 + 进程结束兜底，不做引用循环检测。

## 1. 总体架构

```
三言源码
  │  py导入("json") / 导入c "m.san桩"
  ▼
┌─────────────── 三态信封边界（§2，唯一出入口）───────────────┐
│  层 A：Python 桥（ops/py_bridge_ops.py，解释器 only）        │
│    进程内 importlib + PyHandle 句柄注册表 + 封送表（§3.2）    │
│  层 B：C 声明导入（两半）                                    │
│    离线：scripts/c_bind_gen.py  .h ──pycparser──▶ manifest   │
│           manifest ──▶ <lib>.san 桩（解释器用）              │
│                     └─▶ LLVM extern 声明+链接参数（编译用）   │
│    在线：ops/c_ffi_ops.py  ctypes 按 manifest 调用           │
└──────────────────────────────────────────────────────────────┘
统一门控：SANYAN_FFI 环境开关（默认关）+ 沙箱() 可禁 + agent 隔离条款（§5.1）
```

**执行后端矩阵**（诚实声明，写进手册）：

| 路径 | Python 桥 | C 调用 |
| --- | --- | --- |
| 解释器（--eval / REPL） | ✅ | ✅ ctypes |
| 字节码 VM | ❌ 编译期报错* | ⭕ 开放问题#1 |
| LLVM 原生编译 | ❌ 编译期报错* | ✅ extern+链接（M4） |

\* 明确报错 `py导入 仅解释器路径支持`，绝不静默吞掉——两后端能力面不对称必须显式。

## 2. 三态信封（边界语义核心）

### 2.1 形状

外调**一律**返回信封（三言字典）；绝不直接抛宿主异常穿透到三言层：

```
{ '判': TritValue(±1/0, confidence=c),   # 三态判定，置信度在此
  '值': <封送后的返回值 | PyHandle | C值>,  # 判=真 时有意义
  '错': '<异常类型>: <消息前200字>',        # 判=假 时有意义
  '源': 'python' | 'c' }                   # 排障用
```

### 2.2 判定规则

| 外部事件 | 判 | 置信度 | 值/错 |
| --- | --- | --- | --- |
| 正常返回 | 真(1) | 1.0 | 值=封送结果 |
| 抛异常（Python）/ ctypes 调用抛错 | 假(-1) | 1.0 | 错=类型+消息 |
| 超时（若设 `py调超时`）| 可能(0) | 0.5 | 错='timeout' |
| 模块/符号不存在 | 假(-1) | 1.0 | 错=ImportError/AttributeError |
| FFI 未开启（SANYAN_FFI≠1）| 假(-1) | 1.0 | 错='FFI 未启用（安全默认）' |
| C 函数返回但按 manifest 错误惯例命中（§4.4）| 假(-1) | 0.9 | 值仍附原始返回 |

注意：**"假"表示"调用这件事失败了"，不是外语返回值 False**——Python 返回 `False`
封送为 `值=假(TritValue -1)` 而 `判=真`。判定通道与载荷通道分离，这正是信封存在的理由。

### 2.3 与既有算子互操作（需一处小扩展）

现状：`解包()/或解()/链()` 工作在裸 `TritValue`（判定与置信一体，无载荷通道）。
扩展：**`解包(信封)` 识别"含 `'判'` 键的字典"**——判=真 → 返回 `'值'`；判=假 → 抛
`SanyanRuntimeError(信封['错'])`；判=可能 → 返回默认值参数（无则抛）。`或解` 同理。
向后兼容：裸 TritValue 行为不变（既有 5 个测试是回归钉）。`匹配3(信封判(env)){…}`
提供 `信封判()` 取出 `'判'` 供三态分支。

写法示例（进手册）：

```
令 j = 解包(py导入("json"))
令 s = 解包(py调(py取(j, "dumps"), 字典("a", 1)))     # '{"a": 1}'
匹配3(信封判(py调(f, x))) { 真 → 继续, 假 → 记录错误, 可能 → 重试 }
```

## 3. 层 A：Python 桥详细设计

### 3.1 算子面（`ops/py_bridge_ops.py`，注册进 ops registry）

| 算子 | 签名 | 语义 |
| --- | --- | --- |
| `py导入` | `(模块名) → 信封` | `importlib.import_module`，句柄进注册表并缓存（同名幂等）|
| `py取` | `(句柄, 属性名) → 信封` | `getattr`；结果按 §3.2 封送（可调对象/复杂对象→新句柄）|
| `py调` | `(句柄, 参数…) → 信封` | 调用可调句柄；入参按 §3.2 反向封送 |
| `py项` | `(句柄, 键) → 信封` | `obj[key]`（下标语义，补 py取 的属性语义）|
| `py列` | `() → 值` | 列出活跃句柄（id、repr 前 80 字、引用计数）——排障/教学 |
| `py释` | `(句柄) → 真` | 从注册表移除强引用；重复释放幂等返回真 |

阶段 2 语法糖（动 sugar/ 解析器，M2）：`导入python "json" 为 j` 展开为
`令 j = 解包(py导入("json"))`——失败即抛，与既有 `导入` 的失败语义一致。

### 3.2 值封送表（marshalling）

**Python → 三言（返回值方向，浅转换 + 句柄兜底）**

| Python | 三言 | 备注 |
| --- | --- | --- |
| `True` / `False` / `None` | `真` / `假` / `可能` | **三态天然映射**；有损（回程 `可能`→`None`）|
| `int` / `float` | 数 | 直通 |
| `str` | 串 | 直通 |
| `bytes` | 串（utf-8, errors='replace'）| 阶段 1 从简；无损字节流列开放问题#2 |
| `list` / `tuple` | 三言列表 | **只转一层**，元素递归按本表；深容器出现句柄 |
| `dict`（键全为 str）| 三言字典 | 同上浅转换 |
| 其它一切（对象/模块/可调/生成器…）| `PyHandle` 句柄 | 不透明，靠 py取/py调/py项 操作 |

**三言 → Python（入参方向，深转换）**：`真/假/可能 → True/False/None`；数/串直通；
列表/字典**深转换**（入参方向不会产生句柄需求）；`PyHandle` 解回原对象（这使
`py调(f, 句柄)` 能把 Python 对象原样传回 Python——零拷贝管道）。

**PyHandle**：`{'__py_handle__': int_id}` 包装；进程级注册表 `dict[int, object]` 持强引用
（防 GC）；`py释` 删条目；进程退出兜底清空。句柄跨差分/序列化无意义——`序列化()` 遇句柄
按假拒（fail-closed）。

### 3.3 异常映射

宿主异常在算子内**全捕获**（`except Exception`）→ 信封 `判=假`，`错=f'{type(e).__name__}:
{str(e)[:200]}'`。`KeyboardInterrupt`/`SystemExit` 不捕获（用户意志直通）。三言侧永远
拿信封，绝无裸 Python traceback 穿透（教学一致性 + agent 日志可判读性）。

### 3.4 回调：阶段 1 禁止

`py调` 入参含三言函数值 → 信封 `判=假，错='回调暂不支持（阶段1 fail-closed）'`。
原因：重入 evaluator 的栈语义、异常双向翻译、句柄生命周期三者都要设计，收益却排不上
（numpy/json/requests 主流用法不需要回调）。列开放问题#3，等真实需求。

### 3.5 生命周期与缓存

- 模块句柄按名缓存（`py导入("json")` 幂等返回同句柄）；属性/调用结果句柄**不**缓存。
- 注册表上限 4096 句柄，超限信封报假（`错='句柄泄漏疑似：超上限'`）——教用户 `py释`，
  也防 agent 生成的失控循环把宿主内存拖死。

### 3.6 安全（与 P5 / agent 红线对齐，条款写死）

1. **默认关**：`SANYAN_FFI` ≠ `'1'` 时六个算子全部注册为"报假桩"（信封拒绝，不 raise
   ——语法可解析、语义安全拒，教学示例在未开启环境也能跑出可读结果）。
2. **沙箱可禁**：`沙箱("py导入","py调",…)` 走既有 `core.sandbox.restrict` 机制生效。
3. **Agent 隔离条款**：自更新闭环（run_self_update）**不设** `SANYAN_FFI`——agent 子
   进程环境里 FFI 恒为关。若未来任务需要，须人工显式开启并写入 REFACTOR_PLAN 风险记录。
   `py调` 本质是任意代码执行——它与 run_shell 白名单化（REFACTOR_PLAN 长期条目）同属
   一个威胁面，S4 考官域保护不覆盖它（FFI 是"选手能力"不是"考官"），靠环境开关隔离。
4. **密钥面**：文档明示——FFI 开启时三言程序可读 `os.environ`，`SANYAN_API_KEY` 的保护
   前提是"不给不受信 .san 开 FFI"。差分/测试夹具一律不开。

### 3.7 与差分 oracle / 双后端的口径

- **差分排除**：含 `py导入`/`py调` 的程序不进 `DifferentialVerifier` 用例集（FFI 有
  IO/非确定性，解释器 vs VM 一致性对它无定义）。实现：差分用例静态扫描源码含 FFI 算子
  名即跳过并记 `skipped_ffi` 计数——**跳过要可见**，不许静默缩水。
- **编译/VM 路径**：compiler 不经 ops registry（实测 `grep from ops.registry` 仅
  core/ 三处）——`py导入` 在编译路径直接报错（见 §1 矩阵）。录制回放（把外调结果录进
  manifest 供 VM 重放）列开放问题#4，非目标。

### 3.8 守护测试清单（`tests/test_py_bridge.py`，全部不依赖网络）

1. 封送往返：True/False/None↔真/假/可能、数/串/浅列表/浅字典、深容器出句柄。
2. 信封：`py导入("json")` 判真；`py导入("不存在模块")` 判假带 ImportError；
   `py调` 抛异常→判假；`解包(信封)` 三分支 + 裸 TritValue 兼容回归钉。
3. 句柄：幂等缓存、py释 幂等、上限报假、序列化遇句柄拒。
4. 门控：未设 SANYAN_FFI 时六算子全报假桩；沙箱禁用生效。
5. 回调：传三言函数 → fail-closed 信封。
6. agent 隔离：run_self_update 的环境准备**不含** SANYAN_FFI（在 test_selfupdate_cli 加钉）。

### 3.9 工作量

M1（算子+封送+信封+门控+测试）2-3 天；M2（解包扩展+语法糖+手册章节）1-2 天。

## 4. 层 B：C 声明导入详细设计

### 4.1 两半结构

- **离线**：`scripts/c_bind_gen.py <头文件> --lib <so/dll名> [-I 目录…] [-D 宏…]`
  → 产 `<名>.ffi.json`（manifest）+ `<名>.san`（桩模块）。生成物**入库**（人审过再用，
  与"绝不自动合并"同一哲学——生成器出的桩是候选，人是终审）。
- **在线**：`ops/c_ffi_ops.py` 提供 `c载入(manifest路径)`、`c调(库句柄, 函数名, 参数…)`
  ——桩模块把它们包装成自然的三言函数，用户日常只见桩。

### 4.2 声明导入器（pycparser）

- 输入须过预处理：内置调用 `cpp`/`gcc -E`（gcc 缺席时报错退出——与测试套件 gcc-skip
  同口径），附带 pycparser 的 fake libc headers 兜底常见系统头。
- **只取**：函数声明、typedef、struct/union 定义、enum 常量。**不取**：宏函数、内联
  函数体、位域细节（阶段 1 拒）、可变参数函数（manifest 标 `variadic: true`，运行时拒）。
- manifest 形状（示例）：

```json
{ "lib": "mylib", "binary": {"win32": "mylib.dll", "linux": "libmylib.so"},
  "functions": [
    {"name": "add", "ret": "int32", "args": ["int32", "int32"], "err": null},
    {"name": "openf", "ret": "ptr", "args": ["cstr"], "err": "null_ret"} ],
  "structs": {"Point": [["x", "int32"], ["y", "int32"]]},
  "enums": {"OK": 0, "FAIL": 1} }
```

- 桩模块形状（示例，生成注释含源头文件+时间戳+生成器版本）：

```
# 由 c_bind_gen v1 生成自 mylib.h（2026-07-06）——人工审阅后使用
令 __lib = 解包(c载入("mylib.ffi.json"))
函数 加(a, b) { 返回 解包(c调(__lib, "add", a, b)) }
函数 打开文件(路径) { 返回 c调(__lib, "openf", 路径) }   # 返回信封，调用方自判
```

### 4.3 类型映射表（C ↔ ctypes ↔ 三言）

| C | ctypes | 三言 | 备注 |
| --- | --- | --- | --- |
| `int8..64`/`uint*` | `c_int8…` | 数 | 溢出按 ctypes 语义截断，手册明示 |
| `float`/`double` | `c_float/double` | 数 | |
| `char*`（只读语义）| `c_char_p` | 串 | utf-8 编解码，errors='replace' |
| `void*` / 结构体指针 | `c_void_p` | `C句柄`（同 PyHandle 机制，独立注册表）| 不透明 |
| `struct`（按值）| 生成 `ctypes.Structure` | 三言字典 ↔ 字段映射 | manifest 驱动 |
| 函数指针 | — | **拒**（信封假）| 回调统一阶段 1 禁 |
| `...`（变参）| — | **拒** | printf 类不支持 |

### 4.4 错误惯例注释（C 没有异常——信封判定的来源）

manifest 每函数可标 `err`：`null_ret`（返回 NULL→判假）、`neg_ret`（返回<0→判假，
值仍附原始返回）、`errno`（调用后 `ctypes.get_errno()`≠0→判假带 strerror）、`null`
（无惯例，恒判真）。生成器无法推断惯例——**默认 `null`，由人在 manifest 里补注**（这
是"生成物入库人审"的主要审点）。

### 4.5 内存与诚实声明

- 谁分配谁释放：桩层不自动 free；库若返回需 free 的指针，桩里显式包 `c调(__lib,"free_x",h)`。
- **段错误不可捕获**：C 库崩溃 = 三言进程崩溃。手册红字声明；不受信 C 库的子进程隔离
  模式（把 c调 放代理子进程）列开放问题#5——默认不做（延迟×百倍）。

### 4.6 LLVM 协同（C 层独有红利，M4）

同一份 manifest 驱动第二后端：`llvmgen/` 读 manifest 发射 `declare` extern 原型，
`sanyancc` 接 `--link mylib` 把库挂给链接器。验收：同一 .san 桩在解释器（ctypes）与
编译产物（原生调用）下对纯函数（如 `add`）产出一致——**这一小片恰好可以重新纳入差分
口径**（纯函数、无 IO），成为 FFI 里唯一可差分的角落。

### 4.7 守护测试（`tests/test_c_ffi.py`）

自带 fixture：`tests/fixtures/mini.c`（add/echo/返回 NULL 的函数各一）+ mini.h；测试
setup 用 gcc 编成临时 so/dll（**gcc 缺席整文件 skip**——沿用既有环境 skip 口径，skip
数浮动已有集体记忆）。覆盖：声明导入产物形状、四类 err 惯例判定、类型映射往返、变参/
函数指针拒、结构体字典往返、C句柄释放。

### 4.8 工作量

M3（bind_gen + manifest + 桩生成 + 测试）约 1 周；M4（ctypes 运行时 + LLVM extern +
差分小口径回纳）约 1 周。

### 5.1 与 agent 线（REFACTOR_PLAN S0-S6）的关系

完全正交，共享两条纪律：FFI 算子文件**不进** S4 考官域（是选手能力）；agent 子进程
环境恒不设 `SANYAN_FFI`（§3.6 条款 3，随 S4 一起加考官侧断言测试）。FFI 不阻塞 S0-S6
任何一步，反之亦然。

- `docs/llvm.md` 补 extern/链接节（M4 时）。

## 7. 开放问题（评审时定夺）

1. 字节码 VM 是否/如何支持 C 调用（compiler 不经 ops registry——若 VM 有独立 op 表，
   C 层可像 LLVM 一样由 manifest 驱动；先核实 VM 分派结构再议）。
2. bytes 无损通道（阶段 1 utf-8 replace 有损；需求出现再加 `字节串` 类型或句柄化）。
3. 回调支持的设计（evaluator 重入 + 异常双向翻译 + 句柄生命周期三件套）。
4. FFI 录制回放（让含 FFI 程序回到差分口径；工程量大，收益待证）。
5. 不受信 C 库的子进程隔离模式（防段错误连坐；延迟代价×百倍）。
6. `导入python "json" 为 j` 语法糖是否复用既有 `导入` 关键字还是新关键字（sugar 解析
   器改动面评估后定）。
7. **门控范围（M1 实现偏差）**：§3.6-1 原案"六算子全为报假桩"；落地时改为**能力面
   四算子**（py导入/py取/py调/py项）调用时报假，py列/py释 为惰性运维算子不设门——
   FFI 从未开启时注册表恒空无信息可泄，且中途关闭后仍应允许清理句柄。评审时可改回。
8. **入参方向三态映射（M1 实现偏差）**：§3.2 原案"真/假/可能 → True/False/None"——
   但语言层"真即 1"（数字字面量与三态词同为 `TritValue(1)`，运行时不可区分），
   原案会把数值 `-1` 变成 Python `False`（`False==0`，数值失真）、`0` 变成 `None`。
   落地采取**数值直通**（真→1 假→-1 可能→0）；回程方向不受影响（Python 的
   True/False/None 类型可辨 → 真/假/可能 无歧义）。要传真正的 Python True/None，
   可 `py取(builtins句柄, "True")`。评审时定夺是否需要显式 `py真/py空` 常量算子。
