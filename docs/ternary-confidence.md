# 三言 三态 + 置信度 设计规范

> 版本: v1.0 | 2026-06

## 1. 三层模型

三言的值系统由三个正交层次组成：

```
Layer 3: 复合值          TritValue(value, confidence, source)
                          ↓
Layer 2: 连续置信度       c ∈ [0.0, 1.0]    Bayesian probability
                          ↓
Layer 1: 离散三态         v ∈ {+1, 0, -1}    Kleene three-valued logic
```

### Layer 1: 离散三态（Kleene 三值逻辑）

| 字面量 | 整数值 | 语义 |
|--------|--------|------|
| `真` `亮` `有` `是` `开` | +1 | 确定真 |
| `假` `灭` `无` `否` `关` | -1 | 确定假 |
| `可能` `守` `待` `未知` | 0 | 不确定/中性 |

- `可能` 是离散值，不是 0.5。
- `0` 是精确的中性态，不携带"模糊"含义。
- Kleene 逻辑规则：`真 且 可能 = 可能`（不确定吞噬确定）。

### Layer 2: 连续置信度（Bayesian Probability）

- `confidence ∈ [0.0, 1.0]`，默认 1.0。
- 置信度 = 主观概率：对"当前值是否正确"的把握。
- `三态(真, 0.8)` = "我认为值是'真'，但只有八成把握"。
- `三态(可能, 0.5)` = "我确定我不确定"。
- 传播规则：`C_result = C_a × C_b`（独立贝叶斯更新）。

### Layer 3: 复合值（TritValue）

- `value` (trits) — 离散三态值。
- `confidence` (float) — 连续置信度，默认 1.0。
- `_source` (str) — 来源/证据链，默认空字符串。

## 2. 默认置信度规则

| 来源 | 默认置信度 | 理由 |
|------|-----------|------|
| 字面量 `42` `3.14` | 1.0 | 硬编码常量，完全确定 |
| 字面量 `"hello"` | 1.0 | 硬编码字符串，完全确定 |
| 关键字 `真` `假` | 1.0 | 离散三态词，未加信度前视为确定 |
| 关键字 `可能` `未知` | 0.0 | 中性态本身不代表"有把握"，置信度 0 表示"没有任何证据" |
| `三态值(v)` 未指定 c | 1.0 | 显式构造时若省略置信度，视为完全确信 |
| `读(传感器)` | 取决于传感器质量 | IoT 场景核心 |
| `输入("提示")` | 1.0 | 用户直接输入，暂视为确定 |
| 函数返回值 | 输入置信度的乘积 | 贝叶斯链式传播 |

## 3. 信度守恒定律

### 3.1 算术运算（加/减/乘/除/余/幂）

```
C_result = C_a × C_b                   (独立贝叶斯更新)
```

组合多次运算时：
```
C(a + b + c) = C_a × C_b × C_c
```

### 3.2 比较运算（等于/大于/小于/≥/≤/≠）

```
C_result = C_a × C_b                   (两者都不确定，结果更不确定)
```

### 3.3 逻辑运算

```
C(且)  = min(C_a, C_b)                 (取最不确定的)
C(或)  = max(C_a, C_b)                 (取最确定的)
C(非)  = C_a                           (只翻值，不改信度)
```

**设计理由：**
- `且` 取 min：弱项决定全局（木桶效应），只要有一个低信度输入，输出就低信度。
- `或` 取 max：只要有一条高信度路径，输出就有把握。
- `非` 保持：翻"真/假"不改变"有多确定"。

### 3.4 函数组合

```
C(f(g(x))) = C_x × C_g × C_f
```

每层函数调用将信度乘上函数自身的权重（默认权重 = 1.0）。

### 3.5 截断规则

```
C < 0.01  → 截断为 0.0
C > 0.99  → 截断为 1.0
连续传播超过 20 层 → 视为"信息失真"，标记警示
```

## 4. 来源/证据链（Provenance）

每个 TritValue 携带一个 `_source` 字符串字段，记录置信度的来源：

| 来源类型 | _source 值 | 场景 |
|----------|-----------|------|
| 传感器 | `"红外传感器#3"` | IoT |
| 用户输入 | `"用户#老王"` | 社会模拟 |
| LLM 推断 | `"LLM:deepseek-v4"` | Agent |
| 规则推导 | `"规则:借钱场景"` | 规则引擎 |
| 历史记忆 | `"记忆:2026-06-01"` | 记忆系统 |
| 无来源 | `""` | 字面量/默认 |

API：
```
三态(v, c, 来源)           — 构造带来源的三态值
来源(x)                      — 查询 x 的来源
来源链([a, b, c])            — 合并多个来源为证据链
```

## 5. 示例

```python
# 传感器融合
设 s1 = 三态(真, 0.9, "红外传感器")
设 s2 = 三态(可能, 0.4, "温度传感器")
设 s3 = 三态(真, 0.7, "光照传感器")

设 结果 = 融合(s1, s2, s3)

输出(结果)           # 三态(真, 0.82)  来源: "红外+温度+光照"
输出(来源(结果))     # "红外传感器+温度传感器+光照传感器"

# 信度追踪
追踪({
    设 a = 三态(42, 0.9, "传感器A")
    设 b = 三态(10, 0.8, "传感器B")
    输出(a 加 b)     # 52（置信度: 0.72 = 0.9×0.8）
})

# 冲突检测
设 冲突 = 检测冲突(三态(真, 0.95), 三态(假, 0.9))
// → 冲突: 两个高信度来源矛盾  (0.95 vs 0.90)
```
