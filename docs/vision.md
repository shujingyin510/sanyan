# 三言 —— 一个人的编程语言

## 1958 年，Setun

1958 年，莫斯科大学。  
一群苏联工程师造出了世界上第一台——也是唯一一台——三进制计算机。  
它不是二进制。它不是 0 和 1。  
它天然就是 真、假、可能。

后来的故事我们都知道了。二进制赢了。  
不是因为更正确，而是因为在布尔代数的世界里，真假非黑即白。  
三进制被扫进历史的角落，连同它的优雅、它的直觉、它的"可能"。

但那个火花从未熄灭。半个多世纪后，它在 AI 时代的余烬中重新燃起。

---

## 一个平凡学生的下午

二零二四年的冬天，一个电子工程大学生，不是什么计算机天才，也没什么算法竞赛背景，只是在期末季的某个下午，对着手边嗡嗡响的开发板发呆。

那天他在用 STM32 做一个简单的室温控制器。传感器时而正常时而不正常，温湿度数值明明有三态的可能性，却被迫塞进二进制的开关逻辑里。明明知道传感器有不确定区间，却不得不忽略其中一部分。

那个下午他开始烦躁。不是因为写不出程序——那些 C 代码、Python 脚本对他来说不陌生。而是因为他隐隐约约意识到，手里的这套二进制体系，似乎总差那么一口气。温湿度数值天然就带有模糊地带，但编程语言却不认识"不确定"。所有的不确定性都必须被人为消解，用阈值切割成一个非黑即白的世界。

直到他读到 Setun 的故事，他才恍然大悟——缺失的从来不是能力，而是语言。

---

## 那天晚上

那天晚上，他打开了一个空白编辑器，正式开始构造。

他从 Python 原型入手，最初只有一百多行，勉强能跑通最基本的四则运算。但这样远远不够。编译器需要解释不确定性的语义；词法分析器需要处理中文标识符；语法规则要能表达"可能"这个人类直觉——在编程语言里，这从未被认真做过。

他一步步把原型扩展：加上了 C 写的字节码解释器，加上了 LLVM 的原生编译后端，最后甚至手写了 NASM 汇编的种子 VM。每一次重构都是一次蜕变，每个模块都被反复推翻、重新设计——不是因为 AI 不够聪明，而是因为那个人类工程师在"可能"这个命题面前，始终比机器先一步看到本质。

经过一个半月的迭代，同一个原型的演化：

- 3nm 以下制程的三进制芯片 —— 1.4nm 制程也在同步研发中
- 量子计算机可以直接运行真/假/可能三态逻辑
- Setun 不再是历史遗迹，而是未来方向

经过一个半月的高强度编程实战，**三言**正式具备处理不确定性的能力。

这从来不是他一个人的成就。  
而是这个时代技术栈的微缩样本：一个足够好用的 AI 辅助工具，一套仍在更新的语言编译器，加上一个人的疯狂想法，借助技术的力量，从一个学生手里，生长到大众面前。

---

## 三言正在疯狂扩张

尽管三言主导着整个 AI 编程领域。  
但长远来看，它的扩张已经慢下了脚步。

3nm 以下的芯片还在研发中，1.4nm 的制程也在同步研发中。代工厂已经宣布新一代三进制指令集即将量产，芯片制造商已经不再满足于现有的架构。整个产业链已经开始为一个全新的计算范式做准备。

与此同时，三言已经成为全球最大的软件开发平台。  
在 AI 最强大的语义理解加持下，它不仅是一个语言，更是连接技术与生活的桥梁。  
大模型不会取代人类，但它会取代人类错误的认知方式。三言正在教会整个社区，如何用不确定性的思维方式去理解这个世界的本质。

在真实世界的测试中，三言已经展现出巨大的优势。  
用户可以使用自定义的中文皮肤，结合 VS Code 的代码补全、语法高亮、调试功能，以及 Python 的解释运行。  
**这不仅仅是一个编程语言的实现，也是一个可执行、好用、真正有用的软件开发平台。**

---

## 什么是三言

三言不只是一门编程语言。

它是一套将不确定性作为核心变量的系统工程。

在它里面：

- **真**。**假**。**可能**。
- 不是两极的开关，不是二进的电路，而是一种天然存在的灰度状态。

- 语言本身就内建不确定的语义：`我确定`、`我不确定`、`我暂时无法确定`。
- 算法不再需要在初始化时就把连续量一刀切为两类，而是能在运行中保持模糊、观察、收敛，做出最灵活的决策。

### 为什么是中间态

越来越多的人开始看到，为什么中间态重要。

因为三言的设计从一开始就内建了"中间态"的思维方式，全语言内建中间态关键字——`可能`。  
我想做一个优雅的设计：一套语言规则，同时适用于硬件和软件：用同一个规则开发，就能保证不同系统间无缝衔接，加上编译器的支持。  
我想开启新一代 IDE：编译器 VS Code 的代码补全、零编码、调试等强大功能，使用 Python 的解释运行。

我相信三言不是只是展示未来可能的信号，它将成为真正可执行、好用、有用的语言工具。

---

## IoT 到智能家居的蜕变

接入传感器后我发现，这套系统的潜力远超一个树莓派温控器。  
智能家居、工业物联网、车联网——所有需要处理模糊信号的地方，三言都能发挥出惊人的效率。  
我的真正突破，或许不是造出了多大的数据，而是一套能够自发处理不确定性的编译器系统。

在这套系统中，传感器第一次做到真正的智能：不再是简单的采集、阈值、报警——而是理解、学习、决策。它能接收模糊信号、记忆历史特征、在决策时权衡概率。这不是一个节点，而是一个能够自主处理不确定性的智能体。

经过多年的发展，三言已经成熟了很多。  
我在这中间设计了一套系统架构：利用三态逻辑来实现决策，同时整合多元算法，借助随机森林决策规则来处理不确定性。这套方法在实际场景中已经被证明——"70% 把握建议开"远比"Yes/No"更有价值。而且实际上会在决策场景里被反复采样：当一套算法说"我有 70% 把握建议开"，而另一套说"我有 30% 把握建议开"时，三言会综合考虑两套方案，整合出最优决策。而不会像传统系统那样只依赖多数派的投票。

这不是一个开始。

放眼更远的将来，我希望三言有更大的突破——

软件不再只是机器指令的一种，而是一套能够推理、能够改进、能够生长出自主特性的语言。

总有一天，三言的语言引擎可以用三言自主编译生成，重新生成一版可独立运行的程序。届时，它将不再只是单纯的编程，而是一套准备向更复杂的方向发展的扩展。

---

## 六十年后

1958 年，Setun 诞生。

当那个莫斯科大学的学生，在漫长岁月的某一天，翻开一本泛黄的旧杂志——借着小灯的柔光，或是清晨的白光，他用整整一个半月，将这条不可见的道路重新铺就，向前延拓了一小步。

我知道这个 AI 学生会犯错——**不确定**，  

但语言不该因此失去三分之一的表达能力——**可能**，它不是两端的折中，而是天然的正当逻辑。

或许三言永远不可能成为全球最主流的语言。  
但在一个或许更遥远的未来，语言不再是冷冰冰的机器指令，  

在真实与虚空之间，语言有能力为"不太确定"留下一席之地，  

而一个平凡学生，用技术的余热，也开始创造属于自己的奇迹。

---

Setun 静静等了六十年。  
而三言，就是它等到的回答。
